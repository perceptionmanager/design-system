What I measured

I parsed 5,936 CSS declarations: 4,154 in base.css and 1,782 in 597 inline style="" attributes across 16 pages. Every color, size, spacing, radius, shadow and timing value was counted and mapped to a proposed token. The mapping files list each declaration, so every number here can be checked.

The biggest finding isn't the scales

94% of base.css (3,898 of 4,154 declarations) is page-specific, written as :where(.pg-name) .selector. Components are copied once per page instead of defined once. The footer, nav and badge each exist 15 times. Most copies are identical. Where they differ, that's the drift: 14 inner-page hero headings use 7 different sizes (44, 46, 48, 52, 56, 60, 64px).

Turning these into shared components removes far more code than the token work does, and it's what lets the other three products reuse them.

Accessibility fixes built into the tokens

1 · Tertiary text fails contrast on panels and cards

--ink-faint is used 67 times, often for small labels on cards. It reaches 4.0:1 on cards and 4.25:1 on panels, below the 4.5:1 that WCAG 2.2 SC 1.4.3 requires for body-size text. The proposal lifts it to #8B93A1. It stays the same hue and still reads as tertiary, and it passes on every surface.

2 · Text below 12px

46 declarations set text at 9–11px, mostly the mobile badge label (9px on 12 pages). WCAG sets no minimum size, but 9px uppercase text in mid-gray on dark is hard to read. The proposal sets 12px as the smallest size (the caption role).

3 · No reduced-motion support

The site has no prefers-reduced-motion rules. The background blobs loop on 26–36s animations, and 26 elements cycle color over 5s. Motion that starts automatically, lasts more than 5 seconds and runs alongside content likely falls under WCAG SC 2.2.2 (Level A), which requires a way to pause it. The tokens set all durations to 0 when the user prefers reduced motion. The looping ambient animations also need an explicit stop rule in the component CSS.

4 · Pixels → rem

Every font size is in px, so a visitor who raises their browser's default font size gets no change. All tokens are in rem (16px = 1rem). Browser zoom still works either way. This change is about respecting the user's font-size setting.

Already right — keep

:focus-visible rings in cyan (11.4:1), button text on the gradient (6.9:1 or better), and a 40px menu button (WCAG 2.5.8 requires 24px; the system's target minimum is 44px).

What will look different

Of 2,836 mapped declarations, 1,697 (60%) render exactly as they do today. The rest move by a few pixels or a little opacity. The changes you'll actually notice:

  • Body text on mobile goes from 15 to 16px (60 declarations), and 13px text becomes 14px (34).
  • Hero headings match across pages: 60px desktop and 36px mobile on every inner page, 76/42px on the home page. Apply Platform and Enrollment (44px) and Fleet Portal (46px) grow the most.
  • Spacing: 14px gaps become 16px (107 uses) and 18px becomes 20px (52).
  • Tertiary text gets slightly lighter everywhere it's used.

Architecture

1 · Primitives93 raw values. Products never reference these.--pm-color-neutral-800
--pm-space-6
2 · Semantic53 roles. What every product uses.--pm-color-surface-card
--pm-type-heading-md-size
3 · Component32 values for shared components.--pm-card-radius
--pm-button-primary-bg
  • Source of truth: tokens/*.tokens.json in the W3C Design Tokens Format (2025.10 stable). The CSS file and the Figma variables are both generated from it.
  • The --pm- prefix keeps the shared tokens from colliding with each product's own CSS. @layer tokens means a product's own styles always win without specificity fights.
  • css/legacy-aliases.css points today's names (--bg, --ink-dim…) at the new tokens, so the site keeps working while pages migrate one at a time.
  • Figma: three variable collections that mirror the tiers, text styles for the 10 roles, and a Mobile/Desktop mode for the sizes that scale.
  • One known spec gap: DTCG dimensions allow only px and rem, so em-based letter-spacing is stored as a number and output as em. Fluid min/max values live in $extensions.

Decisions I need from you

  1. Ties round up.14→16 and 18→20 spacing, 15→16 and 13→14 type. The site gets slightly airier. The alternative is rounding down, which keeps it tighter.
  2. One hero size for all inner pages (60 / 36px).Today it ranges from 44 to 64px. If some pages were deliberately smaller, that should be a named variant, not a one-off.
  3. Check icons: coral or gradient?4 pages use the gradient and 6 use solid coral for the same component. Pick one, or make the gradient an "emphasis" variant.
  4. Lift tertiary text to #8B93A1.Required for AA. The difference is barely visible, but you should see it in place.
  5. 12px is the smallest text size.Mobile badge labels go from 9px to 12px, so the badges need a little more room.
  6. Dark only for now.The semantic tier allows a light theme later. I'd hold off unless one of the four products needs it.

What's in this package

  • tokens/: primitives, semantic and component token files (DTCG 2025.10). Every reference has been checked and resolves.
  • css/tokens.css: generated custom properties, the reduced-motion rule, and a utility class per type role. css/legacy-aliases.css maps the old names during migration.
  • mapping/declaration-mapping.csv: all 2,836 mapped declarations, each with its source, selector, current value, proposed token, proposed value and whether it changes visually.
  • mapping/value-summary.csv: the same mapping grouped by value, which is the quickest way to review.
  • mapping/component-consolidation.csv: the 55 selectors that are copied across pages.
  • mapping/current-inventory.csv: the raw "before" inventory of all 5,936 declarations, kept as evidence for the case study.
